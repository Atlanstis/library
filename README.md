# 个人知识库

通过 Obsidian 管理的个人知识库。

## 使用方式

在 Obsidian 中选择“打开本地仓库”，打开本项目的 `vault/` 文件夹。笔记、模板和附件按以下管理规范组织；启用附件和模板功能时，将配置路径设为实际使用的对应目录。

笔记、附件与 Obsidian 共享配置纳入 Git；工作区状态、插件运行目录和回收站忽略。

`vault/` 是本项目的 Obsidian 知识库，采用“内容领域 → 独立专题 → 按需设置辅助目录”的结构。文件夹表达内容归属，辅助目录表达整理状态或用途。

## 内容组织

- 在 `vault/` 下随实际内容建立领域目录，目录名称应清晰表达内容范围。
- 领域下可以按需要建立独立专题。各专题根据自身内容选择内部分类、模板和附件组织方式。
- 正式笔记直接放在所属领域或专题内；内容增多后再按主题细分。
- 普通分类目录默认使用所属专题或领域的辅助目录。
- 按需创建与目录同名的入口笔记，例如 `专题名称/专题名称.md`，用于说明范围和链接重要内容。

推荐目录结构如下，领域和专题名称仅作示例，辅助目录按实际需要创建：

```text
vault/
├── 技术/                         # 内容领域
│   ├── 技术.md                   # 领域入口笔记（可选）
│   ├── 通用知识.md               # 直接归属领域的正式笔记
│   ├── _inbox/                   # 已明确属于技术领域的待整理内容
│   ├── _templates/               # 领域通用模板
│   ├── _attachments/             # 领域内多个专题共用的附件
│   └── 数据库/                   # 独立专题
│       ├── 数据库.md             # 专题入口笔记（可选）
│       ├── 索引设计.md           # 专题正式笔记
│       ├── 查询优化/             # 内容增多后细分的普通分类
│       │   └── 执行计划.md
│       ├── _inbox/               # 专题待整理内容
│       ├── _templates/           # 专题专用模板
│       └── _attachments/         # 专题及其普通分类使用的附件
├── 生活/                         # 其他内容领域
│   └── 旅行清单.md
├── _inbox/                       # 归属待定的内容
├── _templates/                   # 全库通用模板
└── _attachments/                 # 跨领域共用的附件
```

## 按需设置的辅助目录

辅助目录统一使用 `_` 前缀，可位于领域、独立专题或 vault 根目录。首次需要存放实际内容时，随内容一同创建相应目录。

| 目录            | 用途与放置规则                                                                                                                  |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `_inbox/`       | 存放待整理内容。归属已明确到专题的放在专题内，归属明确到领域的放在领域内，归属待定的放在 vault 根目录。整理后移入对应内容目录。 |
| `_templates/`   | 存放可复用模板。专题专用模板放在专题内，领域通用模板放在领域内，全库通用模板放在 vault 根目录。                                 |
| `_attachments/` | 存放图片、PDF 等附件。单一专题使用的附件随专题存放，多个专题共用的放在共同上级的辅助目录，跨领域共用的放在 vault 根目录。       |

根目录的辅助目录按需创建，用于归属待定的记录、全库通用模板和跨领域共用附件。

## Obsidian 目录

| 目录               | 约定                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| `vault/.obsidian/` | 存放 Obsidian 配置。共享配置与 snippets 可纳入 Git；工作区状态、缓存及插件运行目录属于本地数据。            |
| `vault/.trash/`    | 存放 Obsidian 删除的文件，作为本地回收与恢复区域，由 Git 忽略规则管理。知识检索范围为当前有效的笔记与附件。 |

## 操作约定

- 每份内容保留一个主要归属，跨主题内容通过链接复用。
- 整理或移动笔记、附件时，同步更新受影响的链接与引用。
- 容易重名的笔记使用包含专题路径的链接，确保引用目标明确。
- 可复用模板存入 `_templates/`，具体笔记内容存入所属领域或专题。
- 按适用范围优先选择专题模板，其次是领域模板、全库模板；共用模板统一维护在适用的上级目录。这是管理约定，自动选择模板需另行配置。
- 调整目录时检查并同步更新 Obsidian 的附件和模板路径配置，确保路径有效。

## 开发工具

引入 Node.js 是为了运行知识库维护工具：Prettier 统一 Markdown 格式，Husky 管理 Git 钩子，lint-staged 在提交时格式化暂存的 Markdown，commitlint 校验提交信息。pnpm 用于安装这些工具并执行相关命令。日常使用 Obsidian 阅读和编辑笔记无需安装 Node.js；参与上述格式化与提交校验流程时需要配置此环境。

推荐使用 Node.js 24（可运行 `nvm use` 切换）和 pnpm 12.10.1：

```sh
npm install --global pnpm@12.10.1
pnpm install
```

## Git 提交信息规则

标题采用 `type(scope): 描述`，scope 可省略，英文冒号后保留一个空格。type 使用小写，例如 `docs`（笔记和文档）、`chore`（工具与配置）、`feat`（新增功能）或 `fix`（修复问题）；描述不能为空，可使用中文，标题最多 100 个字符。

简单变更只写标题即可：

```text
docs: 添加读书笔记
docs(obsidian): 更新知识索引
chore: 更新工具配置
```

需要描述具体变更时，在标题后空一行，再使用 `- ` 开头的正文列表。正文可省略，不限制行长度和大小写；`-` 列表是推荐写法，也允许普通正文段落。

```text
chore: 初始化开发工具及提交规范

- 限定 Node 与 pnpm 版本
- 配置 Husky、Prettier 和 commitlint
- 添加忽略规则与中文 README
```

不要把 `-` 列表项用作首行标题；缺少合法 type、描述或标题与正文之间的空行时，提交会被拒绝。
